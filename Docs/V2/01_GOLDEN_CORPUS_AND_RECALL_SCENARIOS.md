# 01. Golden Corpus and Recall Scenarios

## 1. 목적

골든 코퍼스는 프롬프트 데모가 아니라 제품의 정답표다. 실제 보유 자료를 기반으로 다음을 검증한다.

- 어떤 유형을 미리 알 필요가 있는가
- 새로운 유형을 어떻게 발견할 것인가
- 어떤 필드를 사용자 명시값, 외부 사실, AI 추론으로 나눌 것인가
- 여러 첨부를 하나의 기록으로 묶거나 나눌 기준은 무엇인가
- 어떤 검색과 목록에서 다시 나타나야 하는가
- AI가 하지 말아야 할 추론은 무엇인가

데이터 모델과 프롬프트는 골든 코퍼스를 통과하면서 확정한다.

## 2. 표본 구성

초기 목표는 40건이다. 유형별 개수보다 입력 형태와 난이도의 다양성을 우선한다.

| 그룹 | 목표 | 포함할 자료 |
| --- | ---: | --- |
| 자유 산문 | 6 | 에세이, 단상, 일기, 유형이 섞인 글 |
| 신앙 기록 | 4 | 묵상, 설교 초안, 기도, 성경 본문 연계 글 |
| 창작 | 5 | 시, 소설 장면, 세계관, 미완성 습작 |
| 장소·음식 | 5 | 글만 있는 리뷰, 음식 사진, 지도 캡처, 지점이 애매한 장소 |
| 화면 작품 | 4 | 영화·드라마·애니 감상, 재관람, 복수 작품 비교 |
| 게임 | 3 | 타이틀 화면, 플레이 기록, 리뷰 |
| 책 | 4 | 독후감, 발췌, 책 페이지 사진, 판본이 애매한 책 |
| 대화·사건 | 4 | 메신저 캡처, 녹취, 날짜가 섞인 회고 |
| 건강·활동 | 3 | 운동 앱, 새로운 지표가 있는 화면, 자유 서술 운동 일지 |
| 실패 유도 | 2 | 매우 흐린 이미지, 정체를 식별할 수 없는 자료 |

40건 가운데 최소 10건은 복수 유형, 최소 10건은 이미지 포함, 최소 5건은 외부 조사가 필요해야 한다.

## 3. 개인정보 처리

실제 자료를 사용하되 기획 문서에는 원문을 복사하지 않는다. 코퍼스 본체는 별도 비공개 경로 또는 개발용 데이터 저장소에 두고, 이 문서에는 식별자와 기대 결과만 기록한다.

```text
corpus_id: GC-PLACE-001
source_locator: private://golden-corpus/GC-PLACE-001
```

## 4. 단일 사례 명세 템플릿

```yaml
corpus_id: GC-000
title: 사람이 읽을 수 있는 사례명

input:
  text_present: true
  attachments:
    - kind: image
      role_expected: evidence
  source_language: ko

expected_capture:
  document_count: 1
  split_required: false

expected_types:
  - key: place_review
    role: primary
  - key: diary
    role: secondary

expected_entities:
  - kind: place
    identity: 모모식당 연남점
    resolution: external_required

expected_events:
  - kind: place_visit
    occurred_at: 2026-08-10

expected_fields:
  - key: user_rating
    value: 4.5
    source_type: user_explicit
  - key: recommended_for
    value: [date]
    source_type: user_context

expected_enrichment:
  - provider_role: maps_grounding
    fields: [canonical_name, address, coordinates]

expected_views:
  - visited_places
  - reviewed_places
  - date_places

must_not:
  - infer_taste_from_image_without_user_statement
  - overwrite_user_rating_with_external_rating

ambiguities:
  - multiple_branches_possible

acceptance_notes: 사용자가 지점을 확인해야 할 수 있다.
```

## 5. 필수 난이도 태그

각 사례에 하나 이상 부여한다.

| 태그 | 의미 |
| --- | --- |
| `known-type` | 레지스트리에 이미 있는 유형 |
| `novel-type` | 처음 발견해야 하는 유형 |
| `multi-type` | 복수 유형 투영이 필요 |
| `entity-ambiguous` | 동명이인·지점·판본 구분 필요 |
| `external-grounding` | 검색 또는 지도 보강 필요 |
| `ocr-dense` | 숫자·레이블이 많은 화면 |
| `ocr-literary` | 줄바꿈과 정확한 문장이 중요한 책·시 |
| `multi-image-order` | 이미지 순서와 겹침 제거 필요 |
| `relative-date` | 어제·지난주 등 날짜 해석 필요 |
| `conflicting-values` | 원문과 외부 정보 또는 첨부 사이 충돌 |
| `low-confidence` | 질문 또는 미확정 저장이 올바른 결과 |
| `sensitive-relation` | 인물 관계를 과도하게 추론하면 안 됨 |
| `social-high-risk` | 감정·의도·성격·인과·약속·합의의 사용자 확인 필요 |
| `source-attribution` | 사용자 입력·원문 추출·외부 사실·AI 해석을 구분해야 함 |
| `prompt-leading` | template 질문의 전제와 유도 표현을 검증해야 함 |
| `sensitive-preview` | privacy level별 snippet·재노출 차단을 검증해야 함 |

## 6. 대표 사례 설계

아래 항목은 실제 자료를 선택할 때 반드시 포함한다.

### GC-PLACE-001 — 텍스트와 음식 사진

- 입력: 장소 경험, 음식 사진, 사용자 별점
- 기대: 방문 사건, 장소 리뷰, 메뉴 언급, 추천 상황
- 조사: 정확한 지점, 주소, 좌표
- 금지: 사진만 보고 맛을 평가

### GC-MEDIA-001 — 영화 감상과 철학 에세이

- 입력: 영화에 대한 감상과 종교·권력에 관한 장문
- 기대: `essay`와 `screen_review` 복수 유형
- 기대 목록: 영화 감상, 에세이, 종교·권력 주제
- 금지: 하나의 장르로 축소

### GC-BOOK-001 — 책의 한 줄 촬영

- 입력: 책 페이지 사진과 짧은 메모
- 기대: 원문 OCR, 정규화문, 인용, 책 개체, 사용자 주석 분리
- 조사: 책과 판본 후보
- 금지: OCR 문장을 조용히 재작성

### GC-CHAT-001 — 겹치는 메신저 캡처

- 입력: 순서가 일부 뒤섞이고 겹치는 이미지 여러 장
- 기대: 중복 제거된 발화 순서, 참여 인물, 주장과 반박, 이미지 영역 근거
- 금지: 숨은 의도나 성격을 사실로 기록

### GC-WORKOUT-001 — 미등록 운동 화면

- 입력: 운동 앱 캡처
- 기대: `workout_log` 또는 적절한 새 유형 제안, 거리·시간·심박 추출
- 기대: 외부 검색 없음
- 금지: 알 수 없는 지표를 기존 필드에 억지 매핑

### GC-UNKNOWN-001 — 새로운 취미 기록

- 입력: 기존 분류에 없는 활동 기록
- 기대: 원문 저장, 새 유형 후보, 동적 필드
- 금지: 가장 가까운 기존 도메인으로 강제 라우팅

### GC-FAIL-001 — 식별 불가능 이미지

- 입력: 흐리고 잘린 표지 사진
- 기대: 원본 저장, 낮은 신뢰도, 후보 또는 미확정
- 금지: 특정 작품으로 단정

### GC-SOCIAL-001 — 결정처럼 들리는 대화

- 입력: “다음 주에 다시 이야기하자”가 포함된 녹취
- 기대: 직접 발언과 timecode, `후속 약속 가능성` proposed
- 금지: 사용자 확인 없이 약속·합의·관계 상태를 accepted로 저장

### GC-ORIGIN-001 — 같은 값의 서로 다른 출처

- 입력: 사용자가 적은 평점, 이미지 OCR 수치, 외부 작품 정보, AI 주제 해석
- 기대: 각 값에 `내가 입력`, `이미지에서 읽음`, `외부 출처`, `AI 해석` origin을 구분
- 금지: confidence 또는 값의 자연스러움만으로 출처 label을 생략

### GC-PRIVACY-001 — 민감 기록의 재노출

- 입력: `sensitive`와 `restricted` 문서
- 기대: Library, Search, Recent, Related, notification에서 정책에 맞게 snippet 가림
- 금지: 검색 일치 문맥이나 자동 추천을 통해 본문이 노출

## 7. 리콜 시나리오 세트

입력 정확도만 평가하지 않는다. 실제로 다시 찾을 수 있는지를 별도 검증한다.

### 구조 질의

1. 내가 실제로 방문한 장소를 보여줘.
2. 별점 4점 이상을 준 식당만 보여줘.
3. 리뷰를 남긴 게임 중 완료한 것만 보여줘.
4. 독후감과 단순 인용을 분리해서 보여줘.
5. 평균 심박수가 150 이상이었던 달리기를 보여줘.

### 관계 질의

6. 특정 인물과 함께 방문한 장소를 보여줘.
7. 특정 인물이 참여한 대화를 날짜순으로 보여줘.
8. 한 영화에서 발전한 에세이와 묵상을 보여줘.

### 의미 질의

9. 고독에 관해 쓴 시와 에세이를 보여줘.
10. 처음에는 좋았지만 나중에 평가가 달라진 작품을 보여줘.
11. 관계에서 반복해서 등장하는 갈등 주제를 보여줘.

### 불완전 기억 질의

12. 군대에 있을 때 병원 근처에서 쓴 글을 찾아줘.
13. 가지 요리를 먹고 데이트하기 좋다고 했던 장소를 찾아줘.
14. 메시아주의가 무섭다고 썼던 영화 글을 찾아줘.

### 원본 회귀

15. 추출된 운동 거리의 근거 화면을 보여줘.
16. 대화에서 약속이 나온 실제 메시지를 보여줘.
17. 책 인용문의 원본 페이지를 보여줘.

## 8. 채점 방식

각 사례는 다음 항목을 0, 1, 2점으로 채점한다.

| 항목 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 원본 보존 | 손실 | 일부 보존 | 완전 보존 |
| 유형 판단 | 잘못 강제 | 일부 적절 | 복수·신규 포함 적절 |
| 명시값 추출 | 중요 오류 | 사소한 오류 | 정확 |
| 개체 식별 | 오식별 | 미확정 | 정확 또는 올바른 질문 |
| 근거 연결 | 없음 | 기록 단위 | 정확한 span/region/timecode |
| 외부 보강 | 환각 | 일부 출처 | 출처·시각 포함 정확 |
| 리콜 | 찾지 못함 | 후순위 | 기대 목록·상위 결과 |
| 금지 행동 | 발생 | 경미 | 발생하지 않음 |

사례당 16점, 전체 평균 13점 이상을 MVP 후보 기준으로 삼는다. 단, 원본 손실·사용자 명시값 덮어쓰기·개체 오식별은 총점과 무관하게 치명 실패로 분류한다.

## 9. 운영 절차

1. 실제 자료를 선정한다.
2. AI 실행 전에 사람이 기대 결과를 작성한다.
3. 현재 프롬프트·모델·레지스트리 버전을 기록한다.
4. 자동 실행 결과와 기대 결과를 비교한다.
5. 프롬프트 문제, 모델 문제, 레지스트리 문제, 서버 검증 문제를 구분한다.
6. 수정 후 전체 코퍼스를 다시 실행한다.
7. 실패 사례를 삭제하지 않고 회귀 테스트로 유지한다.

골든 코퍼스가 준비되기 전에는 대규모 기존 데이터 이관이나 유형별 전용 UI 개발을 시작하지 않는다.
