# 링크 보관 사례집 · 목적 기반 분석과 표시

> 결정일: 2026-09-08  
> 상태: 사례 분류와 제품 동작 기획. 신규 수집기·화면·데이터 계약의 구현 완료를 의미하지 않는다.  
> 관계: [45번 링크 보관 계약](./45_LINK_CAPTURE_AND_PROMPT_LIBRARY.md)을 확장한다. 아래 사례는 닫힌 타입 목록이나 플랫폼별 개발 약속이 아니다.
> 구체화: [48번 대표 입력과 화면 검토](./48_LINK_CAPTURE_WORKED_EXAMPLES_AND_UI_REVIEW.md)에서 분할 prompt·인사이트·구도 팁·자막 강의의 합성 입력과 기대 결과를 확인한다.

## 1. 핵심 결정: 플랫폼과 보관 목적을 분리한다

**플랫폼은 가져오는 방법을 결정하고, 보관 목적과 확보된 내용은 분석·화면을 결정한다.**

- 출처/매체: Threads 게시물·답글·텍스트 첨부, Instagram 이미지 묶음·캡션·짧은 영상, YouTube 영상·설명란, 웹 본문·사용자 첨부 등.
- 보관 목적: 내용 이해, 인용, 프롬프트/코드 재사용, 따라 하기, 장면 다시 보기, 시각 참고, 추천 대상 기억 등. 복수 목적을 허용한다.
- 확보 범위: 실제 수집한 게시물·이미지·텍스트·영상 분석 구간. 읽지 못한 자료를 읽은 것으로 취급하지 않는다.

사용자의 메모와 선택은 AI의 목적 제안보다 우선한다. 내용의 성격과 사용자의 의도도 같지 않다. 강의를 ‘내용 학습’이 아니라 ‘슬라이드 디자인 참고’로 저장할 수 있다. 의도가 불분명하면 일반 자료 화면에 제안만 두고 저장을 완료한다.

Threads를 프롬프트 타입, YouTube를 요약 타입, Instagram을 이미지 타입으로 고정하지 않는다. 새로운 유형도 기존 미분류 저장·레지스트리 제안 경로를 이용한다. AI가 새 데이터베이스 테이블이나 실행 가능한 화면 코드를 만들지 않는다.

## 3. 여러 게시물로 나뉜 프롬프트: 연결과 조립은 별개다

### 입력 변형

- 원글과 작성자의 답글에 순서대로 나뉜 경우.
- 답글 관계 없이 독립 게시물 1/3·2/3·3/3으로 올린 경우.
- 첫 글에 그림, 둘째 글에 프롬프트, 셋째 글에 설정/negative prompt가 있는 경우.
- 같은 작가가 비슷한 예시에 다른 버전의 프롬프트를 올린 경우.
- 조각 사이에 문장이 겹치거나, 같은 내용을 번역해 다른 언어로 다시 올린 경우.
- 다른 이용자가 수정안을 답글로 남긴 경우.
- 중간 글이 삭제됐거나, 스크린샷이 잘렸거나, 링크가 역순으로 입력된 경우.

### 묶음 판단

1. 사용자 지정 묶음, 명시적 이전/다음 링크, 같은 시리즈라는 근거와 조각 번호, provider 답글 관계를 각각 근거로 보존한다.
2. ‘같은 묶음’, ‘같은 프롬프트의 연속 조각’, ‘수정 버전’, ‘결과 예시’는 서로 다른 관계다. 답글이라는 이유만으로 프롬프트에 이어 붙이지 않는다.
3. 작성자 동일·게시 시각 인접·유사 이미지·유사 문체는 후보 탐색의 단서일 뿐 확정 근거가 아니다. 관계가 없는 별도 글은 사용자가 여러 링크를 넣거나 관련 자료 후보를 확인할 수 있다.
4. 수집기가 계정 전체나 모든 댓글을 훑지 않는다. 명시된 연결과 허용된 수집 범위 밖에서는 후보/추가 입력 상태로 남긴다.
5. 화면은 ‘확보한 3개 게시물’과 ‘원문의 3/3조각 확인’을 구별한다. 전체 조각 수를 모르면 완전함을 주장하지 않는다.

### 복사 계약

- 개별 조각은 45번의 원문 범위·해시·줄바꿈 보존 계약을 따른다. native text가 없을 때만 OCR 기반임을 명시한다.
- 순서와 연결이 원문 근거 또는 사용자 확인으로 정해졌을 때 `이어 복사 · 3조각`을 제공한다. 조각 사이에 추가하는 줄바꿈 규칙도 명시한다. 이를 단일 게시물의 ‘원문 전체’라고 부르지 않는다.
- 순서 미확정/누락 시 기본 행동은 개별 복사와 `순서 확인`이다. 사용자가 불완전한 조각 묶음을 복사하는 경우에도 누락 표시를 유지한다.
- 원문에 있는 역할 구분을 보존한다. negative prompt, 설정값, 작성자의 설명, 타인의 수정안을 prompt 본문에 자동 합치지 않는다.
- 조립 결과는 조각 ID·순서·구분자·버전이 있는 파생 표현이다. 조각 원문은 변경하지 않는다. AI가 완성한 문장이 필요하다면 별도 `내 변형`으로 생성하고 원문과 구별한다.
- 겹치는 문장과 번역판은 중복/판본 후보로 표시할 수 있지만 원문을 자동 삭제하거나 연속 조각으로 확정하지 않는다. 사용자가 고정한 순서·역할·연결은 재분석이 바꾸지 않는다.
- 여러 예시와 여러 prompt의 대응이 불명확하면 갤러리를 보존하되 개별 짝은 `확인 필요`로 둔다.

## 4. 인사이트와 구도 팁은 서로 다른 지식 자료다

### 인사이트 글

- 짧은 글은 원문 자체가 가장 좋은 기억 단서일 수 있으므로 요약으로 가리지 않는다. 원문 구절/본문을 먼저 보여주고 요지와 주제를 보조로 둔다.
- `글쓴이의 주장`, `글에서 든 이유·사례`, `AI가 해석한 요지`, `내 생각`을 분리한다. 이유가 없는 주장에 AI가 이유를 덧붙이지 않는다.
- 사용자가 선택한 구절이 없으면 AI의 구절 선택임을 표시한다. ‘인상 깊었다’는 사용자의 평가를 자동으로 지어내지 않는다.
- 나중에는 ‘성장을 너무 효율로만 보지 말자던 글’, ‘내가 반론을 적었던 관점’처럼 주제와 내 메모를 함께 찾는다. 보관만 한 글을 내가 동의한 글로 검색하지 않는다.

### Instagram 구도 팁

- 캡션만 저장하거나 OCR 텍스트만 뽑아서는 부족하다. 원래 이미지 순서와 구도선·화살표·비교 장면이 남아야 한다.
- `저자가 명시한 원칙`, `적용 조건/예외`, `해당 예시 이미지·영역`, `따라 해 볼 동작`을 연결한다. 문장과 이미지 대응이 모호하면 연결을 확정하지 않는다.
- 예: 저자가 직접 설명한 ‘인물 앞쪽에 여백 두기’는 추출된 팁이고, AI가 사진에서 관찰한 ‘좌우 대비가 큼’은 시각 분석이다. 둘을 같은 저자 발언으로 저장하지 않는다.
- ‘잘못된 예/좋은 예’, ‘보정 전/후’는 표기나 캡션 근거가 있을 때만 확정한다. 사람이 읽을 수 있는 이미지 원본과 OCR 영역을 함께 남긴다.
- 이미지 영역 근거는 source/snapshot·이미지 hash·원본 크기·좌표계를 함께 참조한다. 화면 리사이즈나 이미지 수정 후 설명이 다른 영역을 가리키지 않도록 한다.
- 화면은 이미지와 그 이미지의 팁을 같은 카드에 놓는다. 데스크톱은 나란히, 모바일은 이미지 바로 아래에 설명을 둔다. 설명 없는 미학 레퍼런스는 팁 화면이 아닌 갤러리로도 볼 수 있다.
- 릴스 형태라면 같은 팁 모듈에 시간 구간을 근거로 붙인다. 빠른 화면에서 빠진 설정은 캡처 추가/해당 구간 확인으로 보완한다.
- 사용자가 직접 찍어 본 결과는 새 사용자 기록으로 원래 팁에 연결한다. 원저자의 예시나 과거 메모를 덮지 않는다.

## 5. YouTube는 내용과 근거를 각각 나눈다

영상 내용, 설명란, 확보된 자막, 댓글, 사용자의 메모를 별도 source로 취급한다. ‘프롬프트는 설명란에서 확보했고 영상은 아직 분석하지 않음’도 정상적인 상태다.

- 강의: 구간별 개념·목차, 다시 듣고 싶은 시점 중심.
- 튜토리얼: 단계와 준비 조건 중심. 원문에 없는 보완 절차는 별도 AI 제안으로만 취급한다.
- 장면 기억: 선택 구간과 내 메모 중심. 전체 요약을 기본 강제하지 않는다.
- 시각 참고/무음 시연: 실제 화면 관찰이 필요하다. 자막만으로 이미지의 색감·구도·동작을 분석하지 않는다.
- 인터뷰: 발언자와 발언 구간 중심. 녹음 시각, 영상 게시일, 언급된 사건 날짜를 합치지 않는다.
- 프롬프트/코드 재사용: native text를 실제로 확보한 설명란/연결 자료를 우선하고, 화면 OCR과 전사는 확보 방식과 정확도 한계를 표시한다.

설명란의 모든 링크를 자동 추적하지 않는다. 목적과 직접 연결된 외부 자료도 별도 출처로 취급하고, 허용 범위/사용자 선택 아래 수집한다. 영상 하나를 저장했다고 전체 재생목록·채널·댓글 수집을 시작하지 않는다.

긴 영상은 범위 선택과 이어서 분석을 지원한다. 선택 범위가 없고 작업 예산을 넘으면 URL을 먼저 보존하고 범위를 제안한다. 자동으로 일부만 분석했으면 어느 구간인지 먼저 표시한다. 내 선택 범위·실제 처리 범위·분석 근거 위치를 별개로 기록한다. 모델이 영상을 샘플링해 분석한 것을 매 프레임 전수 검증으로 표현하지 않는다.

현재 공식 문서는 Gemini에 공개 YouTube URL 입력 경로를 제시하지만, 비공개/일부 공개 영상은 그 경로의 지원 대상이 아니다. 영상 샘플링은 빠른 장면의 세부사항을 놓칠 수 있다. 프로젝트 모델·SDK·계정에서 capability를 확인하기 전 자동 지원으로 표시하지 않는다. [Gemini 영상 이해](https://ai.google.dev/gemini-api/docs/video-understanding), 확인 2026-09-08.

또한 YouTube 공식 자막 다운로드 API는 해당 영상을 편집할 권한을 요구하므로, 아무 공개 영상의 자막이나 공식 API로 받을 수 있다고 설계하지 않는다. 사용자 제공 자막, 허용된 영상 분석, URL만 저장하기를 구분한다. [YouTube captions.download](https://developers.google.com/youtube/v3/docs/captions/download), 확인 2026-09-08.

본 기획은 모델명·유료 플랜·새 외부 서비스 도입을 변경하지 않는다. 검색 결과나 검색용 모델의 배경지식으로 미확보 원문을 대체하지 않는다.

## 6. 혼합 입력과 예외 상황

| 상황 | 결정 |
| --- | --- |
| 한 글에 인사이트·프롬프트·사용법이 섞임 | 대표 화면 하나와 보조 모듈을 조합한다. 문서를 자동 분열시키지 않는다. |
| 여러 링크를 한 번에 붙여넣음 | 기본은 한 Capture 안의 독립 source들이다. 같은 작품/저자라는 이유만으로 원문을 합치지 않는다. 자료 묶음의 공통 메모와 출처별 내용을 구분한다. |
| 같은 영상의 다른 구간을 다른 이유로 저장 | 같은 원본을 참조할 수 있지만 별도의 선택 구간·메모를 가진 기록을 보존한다. canonical URL 중복만으로 덮거나 제거하지 않는다. |
| 수정된 게시물을 다시 수집 | 새 snapshot을 만든다. 이전 인용·복사 조립본·사용자 메모는 당시 snapshot을 계속 참조한다. |
| 삭제·비공개·로그인·유료벽·지역 제한 | 확보한 범위와 사용자 자료를 보존한다. 인증 우회·쿠키 추출 없이 본문/스크린샷/파일 추가 경로를 둔다. |
| 중간부터 보이는 대화·잘린 캡처·OCR 실패 | ‘부분/미확인’ 표시, 누락 구간 추가 가능. 추측으로 연결하거나 채우지 않는다. |
| 라이브·재생목록·지속 추가되는 시리즈 | 자동 상시 감시가 아닌 현재 명시 범위의 snapshot. 회차/구간 선택으로 축소하며 반복 수집은 별도 요청 사항이다. |
| 추천 자료를 저장한 뒤 실제 경험을 기록 | 외부 추천과 내 경험을 별도 기록으로 연결한다. 경험 날짜·내 별점은 사용자 근거로만 채운다. |
| 새 형태의 도표·밈·운동기록·혼합 이미지 | 원본 보존과 범용 필드/갤러리 fallback. 기존 사례에 억지로 넣지 않고 필요한 필드·표시 후보만 제안한다. |

권한이 다른 기록 간 원본 공유로 더 넓은 노출을 만들지 않는다. snapshot·파생 카드·인용·예시·내 변형에도 기존 owner/privacy/재인증 계약을 적용한다.

## 7. 컴포넌트와 가변 데이터의 방향

새 전역 메뉴나 사례마다 전용 route를 만들지 않는다. [20번 확장 계약](./20_ICON_AND_VIEW_EXTENSION_CONTRACT.md)의 등록된 preset·code-owned module·generic fallback을 사용한다.

| 재사용하는 표시 단위 | 주 내용 / 행동 |
| --- | --- |
| 원문·인용 | 선택 범위와 출처, 원문 복사, AI 요지와 내 메모 분리 |
| 재사용 조각 | prompt/code/설정, 개별 복사, 조각 관계·순서·미확인 상태 |
| 이미지와 설명 | 갤러리, 이미지별 팁·관찰·메모, 확대와 근거 영역 |
| 시간 구간 | 선택 구간, 설명/발언, 해당 시점 열기, 분석 범위 |
| 절차 | 목표·조건·순서, 각 단계의 원문/이미지/시간 근거 |
| 발언 흐름 | 작성자/화자, 답글·인용 관계, 선택 가지, 누락 |
| 대상 목록 | 추천된 장소/작품/도구, 출처, 관심과 실제 경험의 구분 |
| 확보 상태 | 원문 확보, 분석, 첨부 보관의 상태를 각각 표시 |

위 목록은 재사용 책임을 정의한다. 기존 renderer/preset으로 가능한 것은 재사용하고, 새 module은 실제 입력으로 반복 가치가 확인된 것부터 만든다. 18개 사례를 18개 DB schema나 component로 번역하지 않는다.

개념적으로 각 파생 카드는 `목적/역할`, `source·snapshot 근거`, `텍스트 범위/이미지 영역/시간 구간`, `제목·내용·구조 필드`, `원문 추출/AI 해석/사용자 값`, `대표 화면 여부·사용자 고정`을 갖는다. 여러 프롬프트의 조립 관계도 이 근거 구조와 연결한다. 정확한 테이블 확장은 구현 설계에서 검증하며 45번의 3테이블 기본안을 사례별로 무작정 늘리지 않는다.

링크 입력의 기본은 **한 기록 안에 원문 출처와 여러 파생 카드**다. 새 독립 문서로 꺼내기는 사용자의 명시적 동작으로 한다. 목록/검색은 같은 기록을 복제하지 않고 카드의 근거 위치를 열 수 있다. 사용자 지정 대표 화면은 재분석이 바꾸지 않는다.

AI 작업도 플랫폼마다 거대한 개별 프롬프트를 만들지 않는다. 먼저 제한된 입력 범위에서 목적·자료 구조·필요 모듈을 제안하고, 필요한 조각만 세부 추출한다. 코드가 관리하는 출력 계약과 source ID/범위 검증을 통과해야 표시한다. 알 수 없는 필드/모듈은 기존 제안·범용 표시 경로로 남긴다. 실제 확보 범위와 파일 보관 성공은 AI의 판단이 아니라 수집 manifest·검증 영수증으로 결정한다.

## 8. 입력과 결과 UX

1. 링크/첨부와 선택적인 한 줄 메모만 받는다. 저장 전에 18가지 카테고리를 고르게 하지 않는다.
2. 저장 영수증을 먼저 준다. 수집·분류·OCR·영상 분석 실패는 원래 저장의 실패가 아니다.
3. 근거 있는 목적 제안에 따라 대표 화면과 우선 행동을 선택한다. 모호하면 일반 자료 화면과 `정리 방식 바꾸기`를 제공한다.
4. 사용자가 바꿀 수 있는 쉬운 말은 `내용 기억`, `따라 하기`, `장면 다시 보기`, `프롬프트 재사용`, `시각 참고` 등이다. 이것도 닫힌 데이터 타입 목록은 아니다.
5. 첫 화면은 목적에 필요한 카드부터 보여주고 나머지는 펼쳐 본다. 주어진 적 없는 내 감상·동의·별점을 AI가 채우지 않는다.
6. 데스크톱은 자료와 관련 설명을 근처에 놓고 inspector는 부가 근거용으로 쓴다. 모바일은 같은 카드 순서를 세로로 배치하고 복사·구간 열기·확대 동작을 hover나 inspector에 숨기지 않는다.
7. 목적/대표 화면을 바꾸는 것만으로 다시 수집하지 않는다. 추가 분석이 필요할 경우에만 새로운 작업과 입력 범위를 표시한다.

### ‘완료’ 대신 무엇이 남았는지 보여주기

| 차원 | 예시 표시 |
| --- | --- |
| 원문 확보 | 링크만 / 선택 게시물 3개 확보 / 2/3조각 확보 / 일부 본문 / 자막 확보 |
| AI 분석 | 미실행 / 대기 / 부분 분석 / 지정 범위 분석 완료 / 재확인 필요 / 실패 |
| 첨부 보관 | 이미지 원본 4장 보관 / 외부 이미지 참조만 / 원본 영상 미보관 |

예: `설명란 프롬프트 확보 · 영상 분석 안 함 · 원본 영상 미보관`. AI 분석 성공 배지 하나로 세 차원을 대신하지 않는다. ‘완료’가 가능하더라도 선언된 범위에 대한 완료이지 계정 전체·모든 댓글·모든 영상 프레임의 완전함이 아니다.

## 9. 회상과 검색의 기준

- ‘그림이 마음에 들었던 생성 프롬프트’: 예시 이미지 + 재사용 조각으로 이동.
- ‘여러 글에 나뉘어 있던 인물 사진 프롬프트’: 조각 묶음과 연결/누락 상태로 이동.
- ‘효율만 추구하면 안 된다는 인사이트’: 원문 구절과 요지, 내 메모로 이동.
- ‘인물을 작게 놓고 풍경을 살리는 구도 팁’: 설명과 대응 예시 이미지로 이동.
- ‘이 기능 설정하는 법’: 절차와 해당 영상 구간으로 이동.
- ‘나중에 가려고 저장한 식당’: 추천/관심 자료만 필터링. ‘내가 갔던 식당’과 분리.

플랫폼은 보조 필터다. 사용자는 Threads였는지 Instagram이었는지 기억하지 못해도 내용과 목적을 통해 찾을 수 있어야 한다. 외부 저자의 주장과 내 의견은 검색 결과에서도 구분하고, 여러 카드가 같은 기록에서 나왔다면 원래 기록으로 묶어 보여준다.

## 10. 우선순위와 다음 구현 전 검증

다음 구현은 먼저 합성 사례를 만들고 수집 가능성과 표시 계약을 검증한다. 본 문서 작성만으로 adapter 활성화나 배포를 진행하지 않는다.

- 1차: URL/수동 원문·이미지 입력, 단일/분할 prompt, 인사이트, 이미지+구도 팁. 사용자 요청의 세 차이를 최소 공통 모듈로 증명한다.
- 2차: 공개 영상 capability 검증 후 강의·장면·영상 속 재사용 조각. 확보 범위와 실제 근거 구간을 검증한다.
- 3차: 절차·추천 목록, 선택 대화 가지·화자별 보기·다중 출처 비교. 필요할 때만 module 확장.
- 별도 범위: 모든 사이트 자동 수집, 라이브 상시 기록, 전체 계정/재생목록 일괄 가져오기, 설치·생성·구매·재게시. 개인용 초기 버전에 포함하지 않는다.

구현 acceptance fixture는 최소한 다음을 포함한다.

1. 같은 Threads 출처의 prompt와 인사이트가 다른 대표 화면을 선택한다.
2. 3개 별도 게시물의 역순 입력, 가운데 조각 누락, 전체 조각 수 미상에서 순서/완전성을 꾸미지 않는다.
3. 같은 작성자의 수정 버전·무관한 글과 타인 답글이 자동 이어 붙지 않는다.
