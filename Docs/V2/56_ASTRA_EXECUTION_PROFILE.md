# Astra 실행 프로필 · 프로젝트 지침 정비

기준일: 2026-09-08. 사용자 요청에 따라 **GPT-6 Astra (`gpt-6-astra`)로 이 저장소를 개발하는 작업 지침**을 정비했다. 모델/API 설정 변경, 앱 내부 Gemini 교체, 제품 완료 판정은 아니다.

## 1. 공식 근거와 적용 범위

공식 Astra 지침은 파일 지시의 영향, 자율 실행, 병렬 위임, 간결한 전달, 변경 규모에 맞춘 검증을 조정하도록 안내한다. 이 프로젝트에는 현재 코드와 실제 실패를 기준으로 그 원칙을 적용했다. 성능 향상을 측정한 benchmark로 주장하지 않는다. [공식 Astra prompting 지침](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)

Codex의 프로젝트 지침은 프로젝트 루트부터 작업 디렉터리까지 계층적으로 읽힌다. 루트에는 공통 규칙, `apps/web`에는 앱 전용 규칙을 둔다. 파일을 추가했다고 실행 중인 모든 agent가 자동으로 새 지침을 읽었다고 가정하지 않고, 재개 시 직접 확인한다. [공식 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

현재 실행 환경이 제공하는 모델·추론 설정을 유지한다. 문서에 모델명을 적는 것으로 실행 모델이 변경되지는 않는다. 사용자 전역 Codex 설정·설치 Skill·사용량·과금은 이번 변경 범위가 아니다.

## 3. 이후 작업 방식

작업을 시작할 때 결과, 관련 계약, 현재 실패, 수정 범위, 완료 증거를 정한다. 루틴 선택은 기존 요구에 맞게 결정하고 구현한다. 사용자가 우선순위를 바꾸면 완료된 변경과 진행 중 프로세스를 보존해 전환한다.

독립 작업은 파일 소유권과 증거 계약을 붙여 위임한다. root는 통합과 미공유 영역을 진행한다. 실제 사용 가능한 슬롯·도구를 기준으로 하고, 동일 파일/Next 생성물/긴 전체 회귀를 경쟁시키지 않는다. agent 한도 오류는 동일 실행 반복으로 해결하려 하지 않는다.

검사는 새 결함이나 변경의 영향을 증명하는 데 쓴다. 기존 통과 근거가 유효한데 문서나 표현만 달라졌다는 이유로 1시간짜리 전체 suite를 반복하지 않는다. 반대로 schema·권한·복원 계약 변경은 실제 DB 경로까지 검증하고 최종 통합 검사를 생략하지 않는다. 독립 검토의 RED는 보존하고 수정 후 재실행 결과와 구별한다.

사용자 응답은 결과와 필요한 다음 결정부터 한국어로 간결하게 작성한다. 상세 로그·해시는 기능 evidence에 남긴다. 새 승인·위험 항목을 추측으로 늘리지 않으며, 실제 private corpus·실기기·배포 gate는 유지한다.

## 4. 검증과 한계

문서/명령 링크, 활성/역사 라우팅, Next 관리 블록 보존, 프로젝트 지침 크기, 누락 경로와 명령 정합성을 확인한다. 이 문서 정비만을 위해 앱 전체 build나 회귀를 새로 실행하지 않는다. 이미 실행 중이던 회귀의 최종 결과는 현재 상태 문서에 별도로 기록한다.

초기 정비 당시 검증: 대상 9문서의 로컬 링크 118개에서 누락 0, 설치 Next의 `hasCurrentAgentRules(apps/web)=true`, 기존 `CLAUDE.md=@AGENTS.md` 유지. 당시 루트/앱 두 지침은 약 8.7KB이며 전역 지침을 포함한 실제 런타임 전체 크기 측정은 아니다. 독립 정적 검토에서 경로·문서 지도·관련 evidence 범위·G01 부분 완료 표현 4개를 보완했다. 이후 V1 직접 진입 경로를 추가로 정비했으므로 이 숫자는 최종 변경 후 검사와 구분한다. 실제 새 agent 실행의 행동 개선을 검증한 결과와도 구분한다.

실행 모델 변경이나 공식 대비 처리 속도 개선은 측정하지 않았다. 이 프로필의 성과는 후속 작업에서 재시작·중복 검사·불필요한 질문이 줄면서 기존 완료 기준이 유지되는지로 판단한다. root `AGENTS.md`가 실행 규칙이고, 이 문서는 그 근거/변경 기록이다.
