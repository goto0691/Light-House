## 2. 대표 입력과 결과

### P01. 세 게시물에 나뉜 창가 인물 프롬프트

사용자는 3번 → 1번 → 2번 순서로 링크/본문을 넣는다. 세 본문에는 같은 시리즈명, 버전, `1/3`·`2/3`·`3/3`이 명시되어 있다.

원문 조각:

```text
1/3: 창가에 앉은 한 사람의 옆모습.
2/3: 오후의 부드러운 빛, 배경은 단순하게.
3/3: 눈높이 시점, 자연스러운 색감.
```

3번 글에는 `네거티브: 문자, 로고, 과도한 피부 보정`과 `설정: 화면비 4:5`도 있다.

| 결과 | 값 / 동작 | 근거와 제한 |
| --- | --- | --- |
| 대표 화면 | 프롬프트 조각과 개별/이어 복사 | 입력 순서와 원문 조각 순서를 구분 |
| 조립 순서 | 1 → 2 → 3 | 같은 시리즈·버전·파트의 명시 근거 |
| 이어 복사 | prompt 세 조각 사이에 LF 줄바꿈 1개 | 번호·해설·negative·설정은 포함하지 않음 |
| 화면비 | 4:5 | 원문에서 추출 |
| 모델명 | 미확인 | 비워 둠 |
| 예시 이미지 | 없음 | 필수 입력으로 강제하지 않음 |

`원문 중심`으로 바꾸면 사용자가 넣은 순서 3 → 1 → 2로 원문을 읽는다. 이는 조립 순서를 바꾸는 동작이 아니다.

변형의 핵심:

- 2번이 없으면 `명시된 3조각 중 2개 확보`, 기본 이어 복사 비활성, 개별 복사는 유지.
- 관계와 전체 파트 수를 모르면 `게시물 3개 확보 · 전체 조각 수 미확인`.
- 사용자가 연결·순서를 확인해도 전체 파트 수의 미확인 상태는 사라지지 않음.
- 다른 버전·번역·negative/설명은 이어지는 본문으로 취급하지 않음.

### I01. 효율보다 남겨 둘 시행착오

합성 원문:

```text
모든 시행착오를 줄이면, 나만의 판단이 자랄 자리도 줄어든다.
나는 작은 실패를 되짚으며 다음 선택의 기준을 배웠다.
그러니 빠른 답만 찾기보다, 무엇을 시도했는지도 남겨 보자.
```

합성 사용자 메모: `이 말에 전부 동의하는지는 모르겠다. 내 작업과 비교해 보자.`

| 결과 | 표시 | 의미 |
| --- | --- | --- |
| 기억할 문장 | 원문 첫 문장 | AI의 구절 선택이라는 설계 가정 |
| 글쓴이의 이유 | 작은 실패를 돌아본 경험 | 원문 2행 근거 |
| 요지 | 글쓴이는 실패를 돌아보는 경험이 판단 기준을 기르는 데 도움이 되었다고 말함 | AI 해석의 기대값, 사실 검증 아님 |
| 내 생각 | 사용자가 입력한 메모 | 동의/반론 여부는 별도 확인 전 비워 둠 |

화면은 원문 구절 → 원문에 있는 이유 → AI 요지 → 내 생각 순서다. 인용 문장만 확보한 변형에서는 이유·권유를 보여주지 않는다. AI 정리에 실패해도 원문과 사용자 메모는 남는다.

### C01. 인물 앞쪽 여백과 수평선 구도 팁

합성 캡션:

```text
1번: 인물이 바라보는 쪽에 여백을 둡니다.
2번: 수평선이 기울지 않았는지 확인합니다.
걷는 인물을 풍경과 함께 담을 때 적용해 보세요.
```

사진 대신 구도선이 있는 합성 도해로 이미지/설명 대응을 검토한다. fixture에는 이미지 크기·정규화 영역의 가상 메타데이터만 있으며 실제 사진 파일·검증된 hash는 없다. 화면용 도해는 배치 검토용이며 fixture 영역을 실제 이미지 픽셀에 대조한 결과가 아니다.

| 결과 | 표시 | 의미 |
| --- | --- | --- |
| 첫 팁 | 인물이 바라보는 쪽에 여백 | 캡션 1행 ↔ 예시 1 |
| 둘째 팁 | 수평선 기울기 확인 | 캡션 2행 ↔ 예시 2 |
| 적용 조건 | 걷는 인물을 풍경과 함께 담을 때 | 캡션 3행 |
| 이미지 내 글 후보 | `수평선 O도를 확인` | OCR 미확인, O를 숫자 0으로 자동 교정하지 않음 |
| AI의 시각 관찰 | 도해에서 인물이 왼쪽에 있음 | 저자 발언과 별개인 해석 가정 |
| 카메라/정확한 각도 | 미확인 | 생성하지 않음 |

예시를 넘기면 해당 설명도 함께 바뀐다. 캡션만 있는 변형에는 도해를 원본인 것처럼 채워 넣지 않는다. OCR만 있는 변형에서는 근거 패널에도 미확인 문자열을 그대로 보여준다. 데스크톱은 이미지와 설명을 나란히, 모바일은 이미지 아래에 설명을 둔다.

### V01. 강의 중 02:00–05:00 자막만 확보

합성 입력은 12분 영상의 사용자 제공 자막 일부다. 실제 YouTube URL은 아니며 공식 자막 여부도 검증하지 않았다.

| 시간 | 제공 자막의 내용 |
| --- | --- |
| 02:00–03:20 | 저장한 문장뿐 아니라 당시의 단서도 회상에 도움이 된다는 발언 |
| 03:20–04:40 | 장소와 함께 남긴 메모를 예로 설명 |
| 04:40–05:00 | 단서 수가 기억의 정확성을 보장하지는 않는다는 단서 |

첫 화면에서 `자막 기반 요약`, `사용자 제공 자막 02:00–05:00`, `영상 화면 미분석`, `원본 영상 미보관`을 구별한다. 요약은 화자의 주장을 요약한 설계 기대값이지 심리학적 사실의 검증이 아니다.

- 시연의 시간 버튼은 해당 자막을 선택한다. 실제 외부 영상을 여는 척하지 않는다.
- 제목과 링크만 있으면 내용 요약·구간 목차를 생성하지 않는다.
- 요약 실패 시 `자막 확보 범위 02:00–05:00`과 `요약 처리 범위 미완료`를 따로 표시한다.
- 영상 화면을 보지 않았으므로 슬라이드·동작·표정에 대한 설명은 비워 둔다.

## 3. 컴포넌트 동작 결정

1. **상태는 세 줄로 분리:** 원문 확보, 분석, 첨부 보관. 전체 초록 완료 배지로 합치지 않는다.
2. **주요 행동은 본문 가까이:** prompt 복사, 예시 넘기기/확대, 자막 구간 선택을 inspector에 숨기지 않는다.
3. **원문과 목적별 표현 모두 제공:** 모드 변경은 표현만 바꾸며 새 원문 수집·새 문서 생성을 암시하지 않는다.
4. **사용자의 판단 유지:** 내 메모, 대표 화면, 확인된 조각 순서는 다른 화면을 보거나 상태를 바꿔도 유지한다. 페이지 종료 후 내구성은 이번 시연의 범위 밖이다.
5. **불완전한 입력도 유효한 기록:** 누락을 이유로 원문 읽기와 개별 복사를 차단하지 않는다.
6. **복사 성공의 정확성:** clipboard Promise 완료 뒤에 성공을 알린다. 권한 실패 시 선택 가능한 원문과 수동 복사 동작을 제공한다.
7. **모바일은 같은 내용 순서:** 네 유형을 별도 모바일 화면으로 다시 설계하지 않는다. 설명·경고·주요 행동을 가로 넘침 없이 재배치한다.

## 5. 검증 방법과 해석

fixture 검사:

```powershell
node Docs/V2/fixtures/validate-link-capture-design.mjs
```

화면 검사:

```powershell
node Docs/V2/fixtures/verify-link-capture-ui.mjs <시연-fragment-절대경로> <검증결과-출력폴더> <visualize-render.py-절대경로>
```

- fixture 검사는 사람이 설계한 기대값의 원문·참조·영역·시간 정합성을 검사한다. 기본 결과에 변형의 부분 기대조건을 무조건 병합하지 않는다.
- 브라우저 검사는 네 기본 화면과 주요 예외 전환, 320·360·736·1024·1440px의 밝은/어두운 화면, 360/1024px의 WCAG 자동 검사, 번들 sandbox renderer를 대상으로 한다.
- 브라우저 네트워크 요청은 차단하고 clipboard는 테스트용 대역으로 대체한다. 사용자의 실제 클립보드에는 쓰지 않는다.
- 합성 자료의 오류를 의도적으로 넣은 정합성 검사는 모델이 틀린 결과를 실제로 냈다는 실험이 아니다.
- 실제 이미지/OCR의 정확도, 이미지 hash/영역 왕복, 사용자 계정의 API 접근, 모델의 분류/추출 성능, 원본 보관·백업/복원, 물리 모바일·IME, 제품 전체 접근성은 검증하지 않았다.
