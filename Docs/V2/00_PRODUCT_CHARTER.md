# 00. Product Charter

## 1. 문제 정의

기존 Light House는 개인 정보를 여러 도메인으로 나누고 각 도메인 안에 글을 부속 필드로 저장했다. 그 결과 같은 글이 Zettel, Media, Place, Daily Log 가운데 어디에 속하는지를 먼저 결정해야 했고, 이관 과정에서는 잘못 분류된 데이터와 중복 레코드가 늘어났다.

V2가 해결해야 할 문제는 단순한 데이터 정리가 아니다.

1. 기록할 때 분류 부담이 없어야 한다.
2. 기록의 원문과 맥락이 사라지지 않아야 한다.
3. 장소, 작품, 사람, 사건, 주제가 자동으로 연결되어야 한다.
4. 사용자가 예상하지 못한 새로운 기록 유형도 수용해야 한다.
5. 나중에 불완전한 기억만으로 원하는 기록을 찾을 수 있어야 한다.

## 2. 비전

Light House V2는 사용자의 글을 분류하는 앱이 아니라, 사용자가 남긴 자료를 이해하고 다시 꺼내 주는 개인 아카이브다.

### 북극성 경험

```text
사용자가 생각나는 대로 글을 쓰거나 자료를 붙인다.
→ 원문은 즉시 안전하게 저장된다.
→ AI가 유형, 개체, 사건, 평가, 주제, 필드를 구조화한다.
→ 필요한 경우 외부 정보를 근거와 함께 보강한다.
→ 사용자는 결과를 한눈에 확인하고 필요할 때만 수정한다.
→ 훗날 자연어, 목록, 날짜, 인물, 장소, 작품, 주제로 다시 찾는다.
```

## 3. 목표 사용자 결과

### Capture

- 빈 편집기에서 즉시 글을 쓸 수 있다.
- 클립보드 이미지를 바로 붙일 수 있다.
- 여러 이미지, 녹취, 파일과 짧은 메모를 한 기록으로 올릴 수 있다.
- 분류를 선택하지 않아도 저장된다.

### Understand

- 사용자가 직접 말한 별점, 날짜, 거리, 메뉴, 약속을 실제 필드로 반영한다.
- 장소, 작품, 사람과 사건을 식별한다.
- 에세이, 시, 묵상의 주제와 관련 글을 색인한다.
- 처음 보는 기록 유형에는 새 유형과 필드를 제안한다.

### Enrich

- 장소의 주소·지점·영업 정보, 작품의 감독·배우·출시 정보처럼 외부 사실을 조사한다.
- 외부 값마다 출처와 확인 시각을 기록한다.
- 현재 정보와 과거 경험 당시 정보를 구분한다.

### Recall

- “내가 갔던 장소”, “리뷰를 남긴 게임”, “독후감” 같은 정확한 목록을 만든다.
- “아버지와 돈에 관해 이야기한 기록”처럼 관계와 의미가 섞인 검색을 지원한다.
- 한 기록이 장소 리뷰, 데이트 경험, 일기, 특정 인물과의 사건 목록에 동시에 나타날 수 있다.

## 4. 제품 원칙

### P-01. Write first

사용자는 분류표를 채우기 전에 기록한다. 필드 편집은 기본 입력 경로가 아니라 처리 결과를 고치는 경로다.

### P-02. Preserve the source

원문과 원본 첨부는 정본 근거다. AI가 생성한 제목, 요약, OCR 교정문, 외부 정보가 원본을 대체하지 않는다.

### P-03. One input, many projections

하나의 입력이 여러 문서 유형, 사건, 개체, 목록으로 투영될 수 있다. 하나의 폴더를 선택하도록 강제하지 않는다.

### P-04. Open-world classification

알려진 유형 목록이 세계의 전부라고 가정하지 않는다. 새 유형은 `candidate`로 생성하고 정상 저장한다.

### P-05. Evidence before confidence

AI 신뢰도 숫자만 저장하지 않는다. 텍스트 범위, 이미지 영역, 녹취 타임코드, 외부 URL을 값의 근거로 연결한다.

### P-06. User authority

사용자가 고친 필드는 AI 재처리로 덮어쓰지 않는다. 의견과 평가의 최종 권위는 사용자에게 있다.

### P-07. Progressive structure

처음에는 동적 속성으로 받아들이고, 반복해서 쓰거나 자주 필터링하는 구조만 정식 타입과 인덱스로 승격한다.

### P-08. Graceful degradation

Gemini, 외부 검색, OCR, 임베딩이 실패해도 입력과 원본 열람은 동작한다.

### P-09. Protect source memory

사용자가 직접 적은 것, 원문·이미지·녹취에서 추출한 것, 외부에서 조사한 것, AI가 해석한 것을 시간이 지나도 구분할 수 있어야 한다. confidence 숫자는 숨길 수 있지만 의미 있는 출처는 숨기지 않는다.

### P-10. Memory before assistance

빈 기록에서는 본문이 첫 focus를 받는다. 사용자가 직접 고정한 템플릿을 선택했거나 `도움받아 쓰기`를 연 경우를 제외하면 AI 제안과 자동 템플릿은 사용자의 첫 생성보다 앞서지 않는다.

### P-11. Interpretation is not identity

AI가 감정, 의도, 동기, 성격, 관계 상태, 인과를 해석할 수는 있지만 직접 근거와 사용자 확인 없이 개인의 사실이나 지속적인 정체성 label로 확정하지 않는다. 자기 서사 요약은 근거가 된 기록 수와 기간을 함께 표시한다.

### P-12. Safe resurfacing

민감한 기록을 안전하게 저장하는 것과 안전하게 다시 보여주는 것은 별개다. `privacy_level`은 목록 snippet, 검색 결과, 최근 기록, 알림, 자동 추천, AI 처리 가능 범위에 일관되게 적용한다.

### P-13. Stable task navigation

장소·영화·운동처럼 데이터 유형이 늘어날 때마다 메뉴를 늘리지 않는다. 전역 IA는 `보관함`, `탐색`, `확인할 내용`과 `새 기록`, `검색`이라는 안정된 사용자 과업을 반영하며 desktop과 mobile이 같은 route를 공유한다.

### P-14. Personal-first deployment

V2의 기준 사용자는 한 계정의 개인 아카이브다. 지인에게 배포하더라도 계정별 데이터·설정·AI 처리 경계를 분리하고 shared workspace, 공동 편집, 공개 link를 만들지 않는다. enterprise tenant, public plugin marketplace, 역할 기반 조직 권한을 위해 개인용 UX와 데이터 모델을 복잡하게 만들지 않는다.

## 5. MVP 범위

### 포함

- 통합 입력함: 텍스트, 이미지, 오디오, 문서 파일
- 원본 및 첨부 저장
- Gemini 3.6 Flash 기반 구조화 분석
- Gemini 2.5 Flash 기반 검색·지도 보강
- 동적 유형과 필드 레지스트리
- 개체·사건·관계·평가·근거 저장
- AI 처리 상태와 확인 필요함
- 전체 라이브러리와 상세 읽기 화면
- 구조 필터, 전문 검색, 의미 검색, 자연어 질의
- 자동 목록과 사용자 고정 뷰
- JSON·Markdown·원본 파일 내보내기
- 기존 데이터의 읽기 전용 원본 보존과 점진 투영
- 단일 사용자 workspace와 지인별 독립 account isolation

### 제외

- 프로젝트·할 일 관리
- PRM/CRM 전용 기능
- 습관 형성·알림 엔진
- 운동 코칭과 건강 진단
- 공개 블로그와 협업 권한
- AI 자동 문장 수정과 대필
- 지식 그래프 시각화
- 고급 통계 대시보드
- shared workspace, 조직 권한, 공개 plugin marketplace

제외 기능에 해당하는 자료도 기록할 수 있다. 예를 들어 운동 기록은 저장·검색하지만 운동 프로그램 추천 앱을 만들지는 않는다.

## 6. 주요 사용자 여정

### J-01. 자유 글

1. 사용자가 글을 쓴다.
2. 저장 직후 원문을 읽을 수 있다.
3. AI가 에세이, 묵상, 일기 등 복수 유형과 주제를 제안한다.
4. 관련 인물·작품·과거 글을 연결한다.
5. 사용자는 결과를 무시하거나 수정할 수 있다.

### J-02. 장소 리뷰

1. 사용자가 방문 경험과 별점을 적고 사진을 올린다.
2. AI가 장소 방문, 메뉴, 평점, 추천 상황을 추출한다.
3. 지점이 명확하면 주소·좌표·현재 정보를 보강한다.
4. `방문한 장소`, `리뷰한 장소`, `데이트 장소` 뷰에 반영한다.

### J-03. 운동 화면

1. 사용자가 운동 앱 캡처를 붙인다.
2. AI가 OCR과 화면 이해로 거리·시간·심박 등을 추출한다.
3. 처음 보는 값은 동적 필드 후보가 된다.
4. 새 `운동 기록` 유형은 오류 없이 후보로 등록된다.

### J-04. 대화 캡처·녹취

1. 여러 캡처 또는 녹취를 올린다.
2. 발화자, 날짜, 주장, 사건, 약속을 타임코드·이미지 영역과 연결한다.
3. 특정 인물의 타임라인과 관련 사건 목록에 반영한다.

### J-05. 리콜

1. 사용자가 “작년에 리뷰를 남긴 게임”이라고 검색한다.
2. 시스템은 게임 개체, 리뷰 존재, 날짜 조건을 구조 필터로 변환한다.
3. 의미 검색은 구조 조건으로 찾지 못한 보조 결과에만 사용한다.
4. 사용자는 결과 원문과 근거 필드를 함께 확인한다.

## 7. 성공 기준

### 제품 기준

- 분류 선택 없이 기록을 저장할 수 있다.
- AI 장애 중에도 원문 저장 성공률은 100%다.
- 사용자가 명시한 평점·수치·날짜는 검증셋에서 95% 이상 정확히 반영된다.
- 골든 코퍼스의 90% 이상이 기대한 목록에 나타난다.
- 새로운 유형의 자료가 에러 없이 저장되고 필드 후보를 남긴다.
- 사용자가 기억 기반 질의의 80% 이상에서 목표 기록을 상위 결과에서 찾는다.

### 신뢰 기준

- 모든 외부 사실은 출처와 확인 시각을 가진다.
- 모든 AI 추론은 `ai_inferred`로 구분된다.
- 사용자 수정값은 재분석 이후에도 유지된다.
- 원본과 구조화 결과를 언제든 나란히 확인할 수 있다.
- 사용자 입력이 아닌 핵심값은 화면에서 의미적 출처를 바로 식별할 수 있다.
- 고위험 개인·사회적 추론은 직접 인용 또는 사용자 확인 없이 accepted가 되지 않는다.
- `sensitive`와 `restricted` 기록은 예상하지 못한 preview·추천·알림에 노출되지 않는다.
- 자동 템플릿은 반복 사용만으로 active가 되지 않고 사용자의 명시적 유지 선택을 요구한다.

## 8. 비목표와 위험 통제

| 위험 | 통제 |
| --- | --- |
| 유형 폭증 | 후보 상태, 별칭, 중복 검사, 승격 절차 |
| 필드명 중복 | 의미 기반 canonical key와 alias 레지스트리 |
| 외부 사실 환각 | 2.5 Grounding 또는 지정 API 결과만 외부 사실로 저장 |
| OCR 오류 | 원문 OCR, 정규화문, 이미지 영역 근거 분리 |
| AI 장애 | 비동기 큐, 재시도, `unclassified` 안전 경로 |
| 검색 불안정 | 구조 필터 우선, FTS·관계·의미 검색 조합 |
| 마이그레이션 손실 | 원본 불변, 출처 ID, 무삭제 투영, dry-run |

## 9. MVP 완료의 정의

MVP는 화면 수나 CRUD 개수로 완료 판정하지 않는다. 다음 시나리오가 실제 자료로 통과해야 한다.

1. 텍스트·이미지 혼합 입력이 원본 손실 없이 저장된다.
2. 알려진 유형과 처음 보는 유형을 모두 처리한다.
3. 3.6 분석과 2.5 외부 조사의 역할이 분리된다.
4. 필드마다 출처와 근거를 확인할 수 있다.
5. 자동 목록과 자연어 검색에서 기대 결과를 회수한다.
6. 사용자가 잘못된 값을 수정하고 이후 재처리에서도 유지한다.
7. 기존 데이터 일부를 무삭제로 투영하고 원본으로 돌아갈 수 있다.
